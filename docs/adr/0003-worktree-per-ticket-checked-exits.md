# One worktree per Ticket, and Exits are checked, not claimed

Every Ticket that enters Implementing gets its own git worktree and branch, and its Session works only there. Kiln checks the Exit itself: the branch has commits, the working tree is clean and the tests pass. When the person approves the Review Gate, Kiln merges the branch (or opens a PR if the Project uses PRs) and removes the worktree. On the old board, many cards edited one shared checkout, so uncommitted work overlapped, nobody owned a diff, and cards couldn't close. "Done" was a `[[done?]]` marker parsed out of agent replies, which was fragile (old repo `.scratch\commit-coordination\`, `.scratch\done-marker-followups\`). The cost we accept: Tickets that touch the same code may conflict when they merge, and those conflicts surface at merge time, not while the agents are working.
