# Kiln owns one layered permission Policy

Kiln decides what Sessions may do through its own Policy over abstract actions: read or write inside the worktree, the Project's known commands, other shell commands, network access by domain, external writes (push, PR, issue comments), and anything outside the worktree. Each action is allow, ask or deny. Policies layer Org → Project (stored in the repo) → Stage, and each lower layer can only tighten the one above. Each Agent Widget translates the Policy into its tool's own settings. An ask pauses the Session and raises a Permission ask; "always allow" writes a narrow, audited rule into the Project's Policy. On the old board, Claude Code's global rules and auto-mode classifier decided, so unattended work stalled on routine steps and the safety rules couldn't be set per repo; and the board's own broker, `approve_mcp.py`, had an "Always allow" bug. Giving every Ticket its own worktree is what makes broad permissions inside the worktree safe.
