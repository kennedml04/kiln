# One core process; Agents never restart it; Kiln is developed on dev instances

The core is one Node process, started when the user logs in (or run in Docker on servers). It supervises its Widgets itself, so there is no tray/watchdog/recovery trio. A `kiln` CLI handles start, stop, status and doctor. Agents never restart the live core: changing a Widget restarts only that Widget, and updating the core is a person's action ("Restart when idle"). When a Ticket changes Kiln's own core, its Session tests the change on a dev instance started from that Ticket's worktree, with its own port and a throwaway data folder. On the old board, agents changed the board they were running inside but weren't allowed to restart it, which produced the restart-when-idle subsystem and the unsolved UAC/session-0 failures. During the rebuild, the new Kiln runs on its own port and data folder, and the old board stays on 8195.
